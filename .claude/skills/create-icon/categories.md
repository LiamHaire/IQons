# Icon Categories

## Purpose

These categories exist solely to organise the icon library into manageable folders. They are **not** intended to be a strict taxonomy and should **never** influence the design, naming or semantics of an icon.

The goals of categorisation are to:

* Keep related icons grouped together.
* Make icons easier to browse and maintain.
* Provide a consistent location for new icons.
* Avoid unnecessary duplication.

Perfect categorisation is **not** required. Many icons could reasonably belong to more than one category. In these cases, choose the category that best represents the icon's **primary concept** and continue.

Consistency is more important than absolute correctness.

---

## General Rules

* Every icon should belong to **one** category only.
* Categorise based on the icon's **primary semantic meaning**, not every possible use.
* Categorisation should **not** influence the icon's visual design.
* Do not create new categories unless explicitly instructed.
* If an icon is ambiguous, choose the closest existing category rather than overthinking the decision.

### Classification Priority

When an icon could fit multiple categories:

1. **Meaning over appearance** – classify what the icon represents, not what it looks like.
2. **Action over object** – if the icon primarily represents an action, categorise it as an action rather than the object involved.
3. **Primary intent over secondary uses** – choose the concept most users would associate with first.
4. **Consistency over perfection** – follow existing patterns within the library.

## Categories

### Navigation

**Purpose**

Icons used to move around an interface or control layout and navigation.

**Include**

* Arrows
* Chevrons
* Back / Forward
* Up / Down
* Expand / Collapse
* Menus
* Pagination
* Breadcrumbs
* Tabs
* Layout controls
* Direction indicators
* Fullscreen controls

**Exclude**

* Search → **Search & discovery**
* CRUD operations → **Data actions**

---
